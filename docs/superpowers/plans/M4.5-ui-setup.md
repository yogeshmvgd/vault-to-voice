# M4.5 — Setup actions in the UI (ingest / style / ideas)

**Goal:** the user can do everything from Streamlit: index the vault, build the style profile
and find ideas, with the same logic the CLI uses. Reverses the M3 "CLI-only" decision at the
user's request.

**Architecture:** one shared module `vault_to_voice/setup_actions.py` holds the three actions
(`ingest_vault`, `build_style`, `find_ideas`), taking explicit dependencies (settings, manifest,
index, embedder, llm, store). The CLI commands and `RunService` both call it. The service
guards with a maintenance lock: a setup action is refused (409) while any post run holds a
thread lock or another setup action runs; a post run is refused while a setup action runs.
Unexpected failures become `ActionFailed` (500, message only, no traceback).

**Tests:** offline (FakeLLMClient + HashEmbedder); `make_service` now points settings at the
flat test vault and the fake LLM also answers OpinionScore / ToneSummary / ClusterLabel.

## Task 2 — API endpoints
- `GET /config` → vault_path, vault_format, llm_model, embedding_provider, data_dir, outbox_dir
  (never keys). `POST /ingest {"no_score": bool}` → report + stats. `POST /style` → version,
  path, tone, voice_notes. `POST /ideas/detect` → ideas list; out-of-sync → 409.
- Service: `_maintenance` lock; 409 while a thread lock is held / another action runs; post
  runs 409 while an action runs. Tests: TestClient flows, 409s, no secrets in /config, 500
  message without traceback.
